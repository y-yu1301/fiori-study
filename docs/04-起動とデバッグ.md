# 04. 起動・動作確認・デバッグ（Maven / Spring Boot）

> ⚠️ 現在は独立プロジェクト構成です。バックエンドは各プロジェクト配下で起動します
> （例：アプリA は `cd A-cap/srv && mvn spring-boot:run` → 4004、
> アプリB は `cd B-cap/srv && mvn spring-boot:run` → 4005）。
> フロントは `cd A-ui5 && npm start`（8082）、
> `cd B-ui5 && npm start`（8083）。全体像は
> [07-マルチプロジェクト構成.md](07-マルチプロジェクト構成.md) を参照。
> 本章のデバッグ手法（ステップ実行・OData クエリ）は各バックエンドでそのまま有効です。

## 起動する3つの方法

CAP Java は Spring Boot アプリなので、起動手段が複数あります。用途で使い分けます。

| コマンド | 中身 | 開発サーバのポート | いつ使う |
|---|---|---|---|
| `cds watch` | Maven を呼びつつファイル変更を監視。cds-dk がポートを 4004 に設定 | **4004** | ★開発中の基本 |
| `mvn spring-boot:run` | Maven から直接 Spring Boot 起動 | A-cap は **4004**、B-cap は **4005**（各 `application.yaml`） | Maven の挙動を確かめたい時 |
| VS Code の「Run and Debug」 | Application.java をデバッガ付きで起動 | A-cap は **4004**、B-cap は **4005**（各 `application.yaml`） | ★ブレークポイントを張りたい時 |

★開発は `cds watch` または `mvn spring-boot:run` でバックエンドを起動し、
日常的に見る API は A-cap が **http://localhost:4004**、B-cap が **http://localhost:4005** です。
画面は別プロジェクトの UI5 開発サーバで、A-ui5 が **http://localhost:8082**、
B-ui5 が **http://localhost:8083** です。

## 動作確認（OData を叩く / `cds watch` 起動時 = 4004）

```
http://localhost:4004/                                    … サービス一覧
http://localhost:4004/odata/v4/CatalogService/Books       … 本の一覧(JSON)
http://localhost:4004/odata/v4/CatalogService/Authors      … 著者一覧(JSON)
```

OData のクエリも使えます（学習に便利）：
```
.../Books?$select=title,price               … 列を絞る
.../Books?$filter=stock gt 10               … 在庫10超で絞る
.../Books?$expand=author                    … 関連の著者を展開
.../Books?$orderby=price desc&$top=3        … 高い順に3件
```

## ビルドだけ・パッケージだけしたい時

```bash
mvn clean install         # クリーンビルド＋テスト＋.jar 作成（現場のCIと同じ流れ）
mvn -o spring-boot:run    # -o はオフライン。依存取得済みなら起動が速い
```
成果物は `srv/target/fiori-study-exec.jar`。これ単体でも `java -jar` で動きます。

## デバッグ（Javaならでは）

1. VS Code 左の「Run and Debug」→ `Application` を選んで起動（虫アイコン）
2. `srv/src/main/java/**/*.java` のカスタムハンドラ（→[06章](06-Javaカスタムロジック.md)）に
   ブレークポイントを置く
3. ブラウザや Fiori 画面から操作すると、その行で処理が止まりステップ実行できる

> Node版は `console.log` 中心でしたが、Java版は**本格的なステップデバッガ**が使えます。
> これは現場作業でも強力な武器になります。

## H2 の中身を覗く（任意）

H2 はインメモリなので起動中だけ存在します。`application.yaml` に H2 コンソールを
有効化する設定を足せば、ブラウザから SQL で中身を確認できます（学習時のみ推奨）。

## よくあるトラブル

| 症状 | 対処 |
|---|---|
| 4004 に繋がらない | 起動ログに `serving CatalogService ... at 4004`（`cds watch`）が出ているか。PORTSタブに4004があるか |
| データが空 | `db/data/*.csv` のファイル名(`namespace-Entity.csv`)と列名が正しいか |
| ビルドが遅い/失敗 | 初回は依存DL。`mvn -U clean install` で更新。ログのエラー行を確認 |
| `.cds` を直したのに反映されない | `cds watch` は自動再ビルド。手動なら `mvn clean` 後に再起動 |
