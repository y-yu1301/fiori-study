# 08. ソースコードの読み方（初心者向けの地図）

新しくこのプロジェクト（CAP Java）に入ったとき、どこから・どう読めば迷わないかの
ガイドです。CAP は「宣言(.cds)が中心、Java は例外的な業務ロジックだけ」という構造なので、
それを知っているだけで読む速度が大きく変わります。

---

## まず結論：追う順番

「**上から下へ ＝ 宣言 → 例外ロジック**」の順で追うと迷いません。

1. **`db/schema.cds`** … どんなデータ（entity・項目・関連）があるか。アプリの地図。
2. **`srv/*.cds`** … 何を外に公開するか（service / projection）＋画面アノテーション。
3. **`webapp/manifest.json`（UI5側）** … 画面のルーティングと、どの OData を見るか。
4. **`src/main/java` のハンドラ** … ここに Java があれば「標準CRUD以外の特別な処理」。
   無ければ純粋な自動 CRUD（Javaを読む必要なし）。
5. **`src/gen`** … 生成物。辞書として参照するだけ（読むが、書かない）。

### 1本のリクエストを端から端まで追う（おすすめ練習）
```
URL  /odata/v4/CatalogService/Books
  → srv/cat-service.cds     … このサービス・公開範囲・アノテーション
  → src/main の該当ハンドラ … あれば（before/on/after）。無ければ自動CRUD
  → DB (H2)
  → JSON で応答
```
「まず `.cds` で"何が"を掴み、Java ハンドラで"特別な処理だけ"を確認する」——これが基本。

---

## `src/gen` と `src/main` の違い（超重要）

| | `src/gen/` | `src/main/` |
|---|---|---|
| 誰のもの | **自動生成**（`cds build` が毎回作り直す） | **人が書く**（あなたのコード） |
| 目印 | 先頭に `@Generated(value="cds-maven-plugin"...)` | その注釈が無い |
| 中身 | `.cds` から作られた Java クラス（`cds.gen.*`） | `Application.java`・イベントハンドラ・`application.yaml` |
| 編集して良い？ | **編集禁止**（次のビルドで上書き消滅） | ここを書く |

- `.gitignore` でも `**/gen/` `**/edmx/` は除外＝「生成物だからコミットしない」。
- `src/main/resources/edmx/csn.json` なども実は生成物。**人が書くのは
  `.cds`・`Application.java`・ハンドラ・`application.yaml` だけ**、と覚える。

---

## アンダーバー有無（`Books` と `Books_`）

同じ Books でも「役割の違う双子」です。生成物 `src/gen` に必ずペアで現れます。

- **`Books`**（無印）… `interface Books extends CdsData`
  → **データ1件の入れ物**。`getTitle()` / `setTitle()` で値を読み書きする。
  「**実データ（行）を扱う**」もの。

- **`Books_`**（アンダーバー）… `interface Books_ extends StructuredType<Books_>`
  → **クエリを組み立てるための「列の参照」**。`.title()` で列を型安全に指す。
  「**どの列か、を指し示す設計図**」。Java で SQL 相当を書くときに使う。

使い分けの実例（→ [06-Javaカスタムロジック.md](06-Javaカスタムロジック.md) で実際に書く）:
```java
// Books_（設計図）で「どの列を条件にするか」を型安全に指定
List<Books> list = db.run(
    Select.from(Books_.class).where(b -> b.stock().lt(10))
).listOf(Books.class);          // 結果は Books（実データ）で受け取る

for (Books b : list) {          // Books（無印）＝1件のデータ
    System.out.println(b.getTitle());
}
```
**覚え方：アンダーバー＝クエリ/構造（どの列か）、無印＝実データ（中身）。**
同様に `CatalogService_` はサービスを指す参照（`CDS_NAME` など）。

---

## 「ファイルが多い」は普通か

はい、CAP では正常です。ただし**分割されているのはほぼ全部 `src/gen`（自動生成）**。
エンティティ1つにつき `Books` と `Books_` が機械的に生えるので数は増えますが、
**あなたが書くファイルは増えません**（今の手書きは実質 `Application.java` だけ）。
「ファイルが多い＝複雑」ではなく「生成物が多いだけ、人の担当は小さい」と読み替える。

---

## 「.cds がメイン、Java は触らない」でよいか

**8割正解**。正確には:

- **モデル・サービス・UI ＝ `.cds`（宣言的）** … アプリの背骨。主戦場。
- **生成された Java（`gen`）＝ 触らない**。
- **ただしカスタムのビジネスロジックは Java を手書きする**（`src/main` のイベントハンドラ）。
  例：「保存前に在庫チェック」「金額を計算して足す」。単純な CRUD だけなら Java ゼロも
  あり得るが、**現場のアプリはこのハンドラ Java が必ずある**。

つまり：**`.cds` が中心 → 生成 Java は触らない → 例外的な業務ルールだけ `src/main` に
Java で書く**。現場で「Java のソースがある」のは、この**ハンドラ部分**。

---

## 生成物と手書きを見分けるコツ

- ファイルの先頭に `@Generated(...)` があれば**生成物**（読むだけ）。
- パスが `src/gen/` 配下なら**生成物**。
- `src/main/` にあり `@Generated` が無ければ**人が書いたコード**（ここを追う）。
