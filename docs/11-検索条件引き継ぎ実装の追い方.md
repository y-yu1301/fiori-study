# 検索条件引き継ぎ実装の追い方

この資料は、List Reportで入力した検索条件をObject Pageへ持ち込み、Object Page内の明細READへ`$filter`として差し込む流れを追うためのメモです。

## 全体像

今回の実装では、検索条件を2つの用途に分けています。

- READ用: Object Page内の`schedules`テーブルへ`$filter`として渡す
- 表示用: Object Pageヘッダーに「検索条件」として表示する

流れは以下です。

```text
List Reportで検索
  ↓
ListReportExt.onBeforeNavigation
  ↓
検索条件を lrContext としてURL/sessionStorageへ保存
  ↓
Object Pageへ遷移
  ↓
ObjectPageExt.onAfterBinding
  ↓
ヘッダー表示用 searchContext モデルをセット
  ↓
ObjectPageExt.onBeforeRebindSchedules
  ↓
schedulesテーブルREADへ sap.ui.model.Filter を追加
  ↓
CAP Java BookSchedulesFilterHandler
  ↓
context.getCqn() に where 条件が入る
```

## 1. List Report側

対象ファイル:

- `A-ui5/webapp/ext/controller/ListReportExt.controller.ts`

入口は以下です。

```ts
onBeforeNavigation(...)
```

これはList Reportの行からObject Pageへ遷移する直前に呼ばれます。

ここでやっていることは4つです。

1. `extensionAPI.getFilters()`から検索条件を取得
2. 取れない場合はList Reportテーブルbindingの`aFilters`から取得
3. `availableDate`をObject Page明細用の`businessDate`へ変換
4. `lrContext`としてURL queryとsessionStorageへ保存

日付項目の変換はここで定義しています。

```ts
const SOURCE_TO_TARGET_PATH: Record<string, string> = {
  availableDate: "businessDate"
};
```

現場で項目を増やす場合は、ここにマッピングを追加します。

```ts
const SOURCE_TO_TARGET_PATH: Record<string, string> = {
  availableDate: "businessDate",
  plant: "plant",
  material: "material"
};
```

## 2. lrContextの中身

`lrContext`はURLに載せる検索コンテキストです。

例:

```json
{
  "filters": [
    {
      "sourcePath": "availableDate",
      "path": "businessDate",
      "operator": "BT",
      "value1": "2026-08-04",
      "value2": "2026-08-12"
    }
  ],
  "search": "夏目",
  "summary": "対象日: 2026-08-04 - 2026-08-12 / 検索ワード: 夏目"
}
```

`filters`はREADへ渡す機械処理用です。  
`summary`はObject Pageヘッダーへ表示する人間向けの文字列です。

## 3. Object Pageヘッダー表示

対象ファイル:

- `A-ui5/webapp/ext/controller/ObjectPageExt.controller.ts`
- `A-ui5/webapp/ext/fragment/SearchContextHeader.fragment.xml`
- `A-ui5/webapp/manifest.json`

Object Pageに遷移すると、まず以下が呼ばれます。

```ts
override.routing.onAfterBinding(...)
```

ここでURL/sessionStorageから`lrContext`を読み、`searchContext`というJSONModelをObject Pageへセットします。

```ts
updateSearchContextModel(this.base.getView());
```

Fragment側ではこのモデルを表示しています。

```xml
<ObjectStatus
  title="検索条件"
  text="{searchContext>/summary}"
  state="Information" />
```

manifestではObject PageのヘッダーFacetとして登録しています。

```json
"content": {
  "header": {
    "facets": {
      "SearchContextHeader": {
        "template": "project1.ext.fragment.SearchContextHeader",
        "stashed": false,
        "title": "検索条件"
      }
    }
  }
}
```

## 4. Object Page明細READへのfilter差し込み

対象ファイル:

- `A-ui5/webapp/ext/controller/ObjectPageExt.controller.ts`
- `A-ui5/webapp/manifest.json`

manifestで`schedules`テーブルのREAD直前イベントを登録しています。

```json
"schedules/@com.sap.vocabularies.UI.v1.LineItem": {
  "tableSettings": {
    "beforeRebindTable": ".extension.project1.ext.controller.ObjectPageExt.onBeforeRebindSchedules"
  }
}
```

実処理は以下です。

```ts
onBeforeRebindSchedules(...)
```

ここで`lrContext.filters`を`sap.ui.model.Filter`へ戻します。

```ts
bindingInfo.addFilter(new Filter({
  path: filter.path,
  operator: filter.operator,
  value1: filter.value1,
  value2: filter.value2
}));
```

これにより、CAPへは通常のOData `$filter`として届きます。

## 5. CAP Java側

対象ファイル:

- `A-cap/srv/src/main/java/customer/fiori_study/BookSchedulesFilterHandler.java`

入口は以下です。

```java
@Before(event = CqnService.EVENT_READ, entity = "CatalogService.BookSchedules")
public void beforeReadBookSchedules(CdsReadEventContext context) {
    logger.info("BookSchedules READ CQN: {}", context.getCqn());
}
```

ここでは処理を書き換えず、CQNログだけを出しています。

成功時のログ例:

```text
BookSchedules READ CQN: {"SELECT":{...,
  "where":[
    {"ref":["businessDate"]},">=",{"val":"2026-08-04","literal":"date"},
    "and",
    {"ref":["businessDate"]},"<=",{"val":"2026-08-12","literal":"date"}
  ]
}}
```

ODataログでは以下のようになります。

```text
GET /Books(...)/schedules?$filter=businessDate ge 2026-08-04 and businessDate le 2026-08-12
```

## 6. 動作確認手順

1. A-capを起動します。

```sh
cd A-cap/srv
mvn spring-boot:run
```

2. A-ui5を起動します。

```sh
cd A-ui5
npm install
npm run typecheck
npm start
```

3. List Reportで`availableDate`を指定して検索します。

例:

```text
2026-08-04 から 2026-08-12
```

4. 任意のBooks行からObject Pageへ遷移します。

5. Object Pageヘッダーに「検索条件」が表示されることを確認します。

6. CAPログで`BookSchedules READ CQN`に`businessDate`のwhereが入っていることを確認します。

## 7. 注意点

`localhost:4005`のMoviesServiceが起動していない場合、既存の映画タイトル連携はスキップされます。今回の検索条件引き継ぎとは別件です。

```text
Skipping related movie title lookup because MoviesService is unavailable
```

このWARNが出ても、Books READが200で返っていれば今回の確認は続行できます。

TypeScript実行には`ui5-tooling-transpile`が必要です。`A-ui5/package.json`にdevDependencyとして定義済みなので、初回は`npm install`を実行してください。
