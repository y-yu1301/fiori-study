# 05. ★H2 と HANA の違い・実務での落とし穴

学習環境では **H2（インメモリ）** を使い、本番(BTP)では **SAP HANA Cloud** を使います。
「ローカルで動いたのに本番で挙動が違う」を避けるため、差を理解しておきます。
（CAP Node.js 版では SQLite でしたが、CAP Java の既定ローカルDBは **H2** です。
考え方＝「軽量DBで学び、本番は HANA」は同じです）

## まず前提：CAP が差を吸収してくれる…が完全ではない

CAP は `.cds` から各DB向けのSQLを生成するので、多くは意識せず動きます。
ただし **DB固有の型・関数・機能**は吸収しきれず、そこが落とし穴になります。

## 主な違い

| 観点 | H2（学習） | HANA（本番） | 落とし穴 |
|---|---|---|---|
| 実行場所 | ローカル・インメモリ | クラウド・永続 | H2 は再起動でデータ消滅（CSVから再構築） |
| データ永続 | しない（既定） | する | 学習では毎回まっさら＝安全。本番感覚とズレる |
| 大文字小文字/照合順 | H2 の規則 | HANA の規則 | ソート順・比較結果が微妙に変わることがある |
| 全文検索・fuzzy検索 | ほぼ無し | HANA 得意 | HANA固有機能はローカルで再現不可 |
| ビュー/計算列の一部関数 | 未対応あり | 対応 | HANA関数を使うとローカルで動かない |
| 日付・数値の精度/丸め | 実装差 | HANA仕様 | 金額計算の丸めズレに注意 |
| ストアドプロシージャ | 基本使わない | 使える | HANA固有の作り込みは移植不可 |

## 実務での指針

- **`.cds` と標準機能の範囲で書く**ほど、ローカル(H2)↔本番(HANA)の差が出にくい。
- HANA 固有機能（全文検索など）を使うなら、**ローカルで完全再現はできない**前提で、
  HANA Cloud に繋いだ環境でのテストを別途用意する。
- **金額・日付**は型と丸めを明示（`Decimal` の桁数指定など）してブレを抑える。
- 「H2で通ったからOK」ではなく、**本番相当(HANA)での結合テスト**を必ず挟む。

## このプロジェクトでの設定

- `srv/pom.xml` に H2 の依存があり、`cds deploy --to h2` で `schema-h2.sql` を生成。
- `srv/src/main/resources/application.yaml` の `default` プロファイルで H2 を使用。
- 本番は別プロファイルで HANA を指す構成に切り替えます（→[06章](06-Javaカスタムロジック.md)末尾）。
